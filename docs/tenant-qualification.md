# Bounded staging qualification — 2026-11-11

This is a reviewable execution plan, not a record of passing infrastructure tests. No production application, credentials, volumes or connected accounts may be used. Large fleet provisioning is outside this bounded run.

## Observed availability

Coordinator's read-only Fly inventory found only personal-org applications grokbot-team (suspended), swarm-team (production live23) and swarm-team-vms (suspended). There is no dedicated staging app. Production secret names reveal Apple OAuth, Composio and existing model/voice configuration but no PostgreSQL, KMS or backup configuration. This cloud workspace has no AWS credentials/profile/CLI. Do not copy production values into staging.

The local qualification daemon can pull images but cannot start policy-constrained containers: cgroup v2 is in threaded mode and domain cpu/memory/pids controllers are unavailable; swap accounting is unavailable too. Evidence: `.context/isolation-implementation/containment-results.txt`. A skipped or failed-to-start containment test is not a pass. Do not remove limits or browser sandboxing to get a green result.

## Bounded execution

1. Finish deterministic implementation tests and migrations locally. Run real local PostgreSQL identity/session/dispatch tests. Record pass/fail/skip separately; do not report fixtures as live-provider validation.
2. Build and scan one immutable candidate. On the disposable staging host, run the constrained container suite, verify non-root/read-only/capability/seccomp/mount/process limits, and verify Chrome sandboxing. Run `RUN_CONTAINER_TESTS=1 CONTAINMENT_TEST_IMAGE=sha256:<local-image-digest> node --import tsx --test tests/container-containment.test.mts` as the trusted host root for mount qualification. Require util-linux `mount`/`umount` with `--no-canonicalize`, a Docker release supporting `bind-recursive=disabled`, and working private nonrecursive read-only binds. Attempt selected-folder writes, path replacement during mounting, nested-mount exposure, host socket, CLI credential, browser profile, database and foreign MCP reads. Revoke a folder during handshake and active execution; fail container removal and confirm host shutdown. Any unauthorized success stops the run. Do not remove resource or mount flags to make the test pass.
3. Start one tenant host and isolated platform services with synthetic data only. Check manifest/DB/volume mismatch fails startup; inspect listeners and firewall behavior including IPv6 and metadata destinations. Keep one active bot, up to three windows, and bounded eight-helper concurrency to exercise the owner's simultaneous-subscription requirement. Measure OOM/resource behavior; do not introduce account queues to hide failures.
4. Exercise a fixed batch of at most 100 synthetic jobs over 30 minutes: login rotation/revocation, queued tool revocation, viewer watch/control substitution, terminal ownership, runtime renewal/lost responses, worker restart and uncertain external-write reconciliation. Verify initial hold, exact-revision readiness, stop/wake, expired refresh replacement and config-file bootstrap replay. Exercise two platform replicas: revoke sessions/native pairings on one and verify the other closes its relays; terminate the LISTEN backend and confirm health 503, relay closure and fresh authorization after reconnect. Verify delegated tenant cookies cannot authenticate any platform account/admin endpoint. Delay cloud app/volume/machine creation until after deletion starts; cleanup must remain pending until the resource outcome is accounted for. Use a controlled upstream fixture for destructive/error scenarios.
5. Add controlled provider credentials only after containment passes. Perform at most 20 read-only provider calls per account and 5 explicit test writes to disposable records. Check another owner cannot select a foreign account and one owner with two accounts always reaches the chosen account. Check MCP SSRF/rebinding/redirect and response bounds against controlled fixtures, not arbitrary networks.
6. Exercise the [isolated recovery/update commands](tenant-recovery-operations.md) with synthetic encrypted backups: foreign host/runtime JWTs must fail; disconnect during download, generation replacement, damaged parts, missing published data and lost completion responses must prevent unsafe activation. Verify source stop/removal, pre-activation rollback, refusal of stale-volume rollback after any run permit, snapshot-era job/message reconciliation and disabled recovered MCP/Mac consent. Confirm old-volume retention never deletes a current or attached volume and waits for actual provider deletion. Separately, once concrete legacy source/target adapters exist, migrate synthetic records with proven credential/file ownership and one authoritative writer. Measure database RPO <=5 minutes, profile age <=24 hours and full restore <=30 minutes, including disk space for encrypted and restored copies. Inject storage/deletion failures and verify durable retry visibility.
7. Archive metrics, image/kernel versions and sanitized findings; remove test credentials, test records, temporary images/VMs/volumes as agreed in the inventory. No automatic deletion outside that inventory.

Single-host testing cannot establish cross-microVM/private-network isolation. After it passes, a separately bounded two-tenant Fly test with two isolated applications/volumes/networks must verify tenant A, including compromised workload root, cannot reach tenant B or use B's runtime/provider/viewer identity. Do not mark that gate passed from shared-host simulation.

## Remaining release gates

All critical/high findings resolved; independent adversarial assessment; real provider authorizations and supported subscription flows; Fly network/volume/runtime semantics; backup storage/IAM/recovery drills; migration/cutover/deletion verification; production monitoring and abort controls. Then separately obtain quota/capacity and budget for 25/100/250/500/1,000 active users, a 1,250-user burst and a 24-hour soak, including 0/10/100% desktop viewing. Evaluate API p95 <500 ms, warm task admission p95 <2 seconds, <1% platform errors, durable accepted work and bounded memory/queues. No single-host result proves 1,000-user capacity.
