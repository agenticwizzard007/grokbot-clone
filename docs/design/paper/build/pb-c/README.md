# PB-C build evidence

PR 1 supplies the shared layout primitives, the exact Paper v3 design pack and the route alignment audit. PR 2 migrates all eleven Settings sections and reduces their visible copy.

The layout samples use local fixtures at 320, 390 and 1280 in both themes. Settings evidence uses `before-{section}-{width}-{theme}.png` and `after-{section}-{width}-{theme}.png` for all eleven sections at the same sizes. The before capture is from untouched main b418b54. No live account was used.

References are generated by `python3.12 docs/design/paper/gen/render.py /tmp/paper-html`. Compare Models, General, API keys, Usage, Permissions and Connected apps against those HTML artboards. Browser chrome and fixture content differ; shared v3 Cards also wrap the formerly flat General rows.

Local verification includes the five-width, two-theme Settings matrix, complete label and provider-mark checks, expanded forms and info popovers, all PB-C alignment routes, navigation, provider health, billing and reauthentication behavior. The full suite has 2,856 passes and the same 70 failures as the untouched baseline, with 24 pre-existing skips. The thirteen-size phone/tablet sweep passes all 338 views.

The counts above include the 22-word desktop Settings navigation and the shell header, and exclude the app sidebar and phone tabs. They count visible text nodes, excluding hidden disclosures and screen-reader-only labels. Theme variants have the same text. Raw measurements for all widths and both themes are committed as before-word-counts.json and after-word-counts.json. Page-only counts are included to make the fixed navigation cost visible.

Copy budget limitations: the required desktop Settings navigation alone exceeds the nine-word MCP budget. Account, Computer and Messaging also exceed the literal desktop totals when their usable controls and navigation are included, while their page content is below the stated 30-percent budgets. Phone MCP needs four words for Back, MCP servers and Add, exceeding the three-word total by one. Models is one word above the artboard when both plans are disconnected. API keys is four words above the desktop artboard because it names the supported Model API and xAI voice roles and retains Server defaults. General was already concise on the current main branch. No controls or required navigation were hidden solely to reduce these measurements.

Backend boundaries: Never ask remains disabled because the backend only supports Standard and Every action approval modes. Gemini was not added as a fake credential option; the provider list uses the existing OpenRouter, Model API and xAI voice capabilities. Usage presents recorded AI requests and OpenRouter cost instead of invented run counts or credit balances. Reported quota percentages are shown only when available. These are the specification differences retained for accurate behavior.
