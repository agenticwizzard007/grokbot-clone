# Legacy skill proposal review

A pending new-skill proposal with a different name from later active skills is still a real candidate. It must not be marked superseded merely because the Bot has learned another skill. The existing status calculation correctly preserves it, and the pending count comes from the same list shown for review.

Legacy proposals remain pending until the owner approves or dismisses them. The pre-#223 adapter stored the proposal actor, source messages, run ID and settings revision, but did not freeze the execution mode or an attended authorization decision. An actor of `foreground` alone does not prove attendance. A retained user job can prove attendance, but the account's current CLI selection cannot establish which mode produced the old proposal. Settings revisions can also have changed since staging. Automatically replaying these rows could activate an API-mode proposal or a change that originally required approval. Opening Skills therefore makes the proposal actionable without guessing past authorization.

Review changes now shows Approve and Dismiss for each pending proposal without requiring the user to expand its diff or find the controls below the evidence. The diff, sources and evaluation remain available by expanding the named proposal. Approve activates a valid candidate and refreshes the active skills and pending count. Dismiss records rejection, removes the candidate from the pending count and retains it under Earlier skill proposals.

The existing authenticated review endpoint successfully approves a local reconstruction of the pre-#223 attended CLI proposal, even when later active skills have different names. A legacy row with no explicit actor metadata is also approvable when its source evidence is valid. No endpoint bypass or customer-data cleanup is needed. Missing or changed evidence, changed conversation generations, stale revisions and conflicting owner protections remain guarded. If an approval is blocked, the error appears beside that proposal and explains that it can be dismissed or replaced with a fresh proposal. Dismissal does not require valid source evidence.

`npm run test:skill-proposal-review` covers legacy approval and dismissal through the real authenticated routes, missing actor metadata, missing or changed evidence, changed generations, current-revision edits and approval-on candidates. Its local Playwright fixture recreates the old staging behavior with a user job and source message. For both CLI selections at 1280 and 390 pixels in light and dark, it verifies visible actions, active skill creation, zero pending counts after review, earlier proposals and recovery from unavailable evidence. Screenshots are saved under `.context/skill-proposal-review/`.

All fixtures use disposable local data. No live sign-in, customer-data mutation or paid model call is required.
