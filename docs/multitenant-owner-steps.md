
## MT-C: Invite onboarding and operator CLI

No external account or secret is needed to build or run the local tests. Live onboarding remains unrun until the isolated platform prerequisites exist.

1. Supply the dedicated staging organization, AWS KMS/S3 setup, Composio platform project and OAuth configuration through the protected process in `infra/platform/staging-bootstrap.md`. Do not reuse credentials from the standalone service.
2. Choose the owned HTTPS platform origin and set `PLATFORM_URL` to that exact origin. Register the Google web callback as `<PLATFORM_URL>/api/auth/google/callback` and Apple web callback as `<PLATFORM_URL>/api/auth/apple/callback`. Configure native Apple client IDs only for the owned native applications. Keep provider identity verification and native PKCE enabled.
3. Run the repeatable directory migration with the separate schema-owner credential. Ensure the operator and serving database roles receive the intended grants for `web_invites` and `web_waitlist`. Keep `DATABASE_URL` in a protected environment, never a command argument or PR.
4. Set `PLATFORM_TENANT_LIMIT=10` consistently on the isolated platform and provisioner roles for the first cohort. Use `policy show`, then `policy set --mode invite --signups-per-day 10 --revision <current-revision>` through `server/dist/platform/tenants-cli.js`. No application administrator account is needed for this trusted operator command.
5. Issue ten separate `invites create --uses 1 --days 7 --note 'First customer cohort'` commands. The CLI prints a code and `<PLATFORM_URL>/?invite=<code>` and sends nothing. Distribute links only through the approved operator process after the existing release gates are satisfied.
6. After reviewing quotas, spend and qualification, raise the cap in cohorts to 25, 50 and 100. Configure the private operations collector to observe `swarm_operations_current_tenants` and `swarm_operations_tenant_limit` using the existing metrics token-file workflow.

See `docs/platform-onboarding.md` for command syntax, waitlist handling and lifecycle behavior. No live resources were created, no messages were sent and no qualification evidence was generated by MT-C.
