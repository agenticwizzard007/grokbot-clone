# Skill proposal sharing and protection

Skill proposals authorize content changes only. New learned skills start private, unlocked, unpinned and managed. A wording proposal on an existing skill retains its sharing scope, project identifier, grants, lock, pin, management flag and supporting files. Explicit resource edits still require the existing fresh-read checks. A proposal cannot silently grant other Bots access or remove an owner's protections.

Sharing and protection changes belong to the authenticated owner controls: the skill scope endpoint validates project recipients in the same account; the skill settings endpoint controls lock, pin and management. Owner changes advance the revision, so an earlier pending proposal cannot overwrite them. The proposal diff includes sharing/protection values, including on historical proposals.

Both staging and owner approval enforce this content-only contract. Pending proposals written by an older release are not rewritten: if their saved sharing/protection values conflict with the current skill (or with private defaults for a new skill), approval returns a conflict and leaves the proposal pending. Reject that proposal and request a fresh one. Do not edit its immutable snapshot, bypass the conflict, or reset owner settings to make it approvable. Rejection remains available without applying any content or sharing changes.

Background learning and curator/refine dispatch validate each call against the advertised tool schema, including native subscription callbacks. Unknown fields, wrong types and oversized inputs fail before implementation. The existing bounded validator runs outside the application thread; dispatch rechecks review ownership, settings and loaded knowledge after that asynchronous boundary. It executes the same detached arguments that were validated. Schema success does not grant access: domain ownership, source, revision, fresh-read, migration-hold and promotion-policy checks still apply.

Deterministic coverage in `tests/native-knowledge.test.mts` and `tests/native-learning-lifecycle.test.mts` includes raw scope injection, ordinary text edits on account/project sharing, retained grants/resources/protections, historical pending snapshots, model/native schema rejection, cancellation during validation and argument replacement during a native callback. These tests use disposable data with network calls blocked. They do not establish real-provider behavior or production tenant containment.
