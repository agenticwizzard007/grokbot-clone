# Native Hermes learning: source map and qualification

Reference: [NousResearch/hermes-agent, f0e7b68e439f8c1962fcf9dcb0341aadf1e2a898](https://github.com/NousResearch/hermes-agent/tree/f0e7b68e439f8c1962fcf9dcb0341aadf1e2a898), MIT. The copied notice is [HERMES-LICENSE](../server/src/knowledge/HERMES-LICENSE).

This is a native adaptation of the learning decisions and prompts. It uses the existing tenant SQLite database, agent jobs, model adapters, tools, usage records and transactional events. It does not start a Python Hermes service or use a global memory filesystem. It does not claim identical prompt-cache bytes, provider internals, or the entire upstream plugin/filesystem surface.

In the table, **Lifecycle** means [tests/native-learning-lifecycle.test.mts](../tests/native-learning-lifecycle.test.mts), **Knowledge** means [tests/native-knowledge.test.mts](../tests/native-knowledge.test.mts), and **Coverage** means [tests/native-learning-coverage.test.mts](../tests/native-learning-coverage.test.mts). Quoted names are maintained test names.

## Copied prompts and substitutions

[agent/learning-prompts.ts](../server/src/agent/learning-prompts.ts) copies the complete pinned `_MEMORY_REVIEW_PROMPT`, `_SKILL_REVIEW_PROMPT`, `_COMBINED_REVIEW_PROMPT` and `CURATOR_REVIEW_PROMPT` constants, including their shared routing/lesson/do-not-capture blocks. It retains active preference/workflow correction signals, loaded-skill-first selection, class-level organization, topical references/templates/scripts, fresh reads, no environment-failure myths and the legitimate no-change outcome. It does not replace these prompts with a short new summary prompt.

| Upstream spelling | Native substitution |
| --- | --- |
| `skill_view`, `skills_list`, `skill_manage` | `read_skill`, `list_skills`, `manage_skill` |
| `skill_view(name)` identity | `read_skill(skill_id)`; file reads still use `file_path` |
| `memory tool`, `target='memory'` | `manage_memory tool`, `target='environment'` |
| `USER.md`, `MEMORY.md` | Tenant-owned user/environment memory stores |
| `~/.hermes/skills/.archive/` | Native recoverable skill archive |
| `hermes curator lock`, `cron=yes` | Owner lock control, `routine=yes` |

The native loop appends bounded source anchors and current authorized database knowledge to these prompts. Full original sources remain searchable and their hashes are frozen for publication; the source index does not replace or trim the originating same-model history snapshot.

## Qualification and deliberate limits

- Native storage, transactionality, tenant scopes, revision/epoch fences and durable event/outbox mechanics are integration additions. Exact Python fork/cache parity is not claimed. The CLI management envelope deliberately gives loop control to the server while preserving the selected provider/model/funding route.
- Normal background review cannot issue business actions, request secrets, acquire new tools through skill text, or execute package scripts. Foreground use of package scripts remains subject to the normal native tool permissions.
- Routine dependencies are conservatively protected from automatic mutation/archive. This implementation does not reproduce upstream cron-reference rewriting during consolidation; it cannot silently break a routine to consolidate its skill.
- Restart cancels reviews that were running and retains any already committed revisions. It does not replay uncertain model mutations. Queued intent survives and runs only when foreground work, owner and settings fences permit.
- Provider-reported input/output counts remain observed counts. When usage is missing, `usageStatus` states that explicitly; a separate conservative character/tool-schema estimate enforces the input budget. The upstream next-iteration aggregate gate is preserved rather than a hard prohibition on the request that crosses the ceiling.
- Legacy idle extraction remains callable for compatibility and its coverage defects are repaired. Root disables its parallel automatic scheduler when the native learning runtime owns dispatch, avoiding an independent default-model billing path.
- Maintained learning tests use disposable databases, deterministic model fixtures, blocked external network and no real sends. They exercise actual detached lifecycle, mutations, transactions and HTTP boundaries. Live model output quality, provider usage precision, prompt-cache economics, and production delivery still require authorized staging qualification; no measured business improvement is asserted here.

Run the focused domain qualification from the repository root:

```sh
npm run typecheck -w server
node --import tsx --test --test-concurrency=1 tests/native-knowledge.test.mts tests/native-learning-lifecycle.test.mts tests/native-learning-coverage.test.mts
```

The coverage test and shared CLI/usage/event modules are integrated from their respective owners; learning commits do not overwrite those owners' implementations.

Latest learning-domain qualification: server typecheck passed; 64 focused tests passed (33 lifecycle/HTTP/adapter tests, 27 retained knowledge tests and four coverage regressions). External sends were blocked. This result is domain qualification, separate from root's combined application/browser/subscription qualification.
